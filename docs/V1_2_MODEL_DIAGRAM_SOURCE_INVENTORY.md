# v1.2 model, diagram, and source inventory

**Scope and method.** Inventory of the 25 English/Korean chapter pairs in `chapters/` and `ko/chapters/` (the standalone EN `resist.html` is not a paired chapter and is excluded). Inspected source HTML for `<script src>`, `sim-*` sections, SVG/figure/canvas elements, external HTTP(S) anchors, and chapter section IDs; compared chapter claim scope with the existing [technical audit](V1_2_TECHNICAL_AUDIT.md) and [critical claim register](V1_2_CRITICAL_CLAIMS.json). Counts below are source-discovery counts, not independent scientific validation. Section anchors are shared in EN/KO where noted; individual-language formula wording and arithmetic still require review.

**Review disposition.** No item in this inventory has received an independent, item-by-item scientific validation as part of this inventory task. Automated discovery and the audit summaries are not such validation. Scientific disposition remains as stated by the technical audit; the v1.2 candidate numerical examples, simulator assumptions, translation equivalence, and diagram-to-source fidelity remain pending wherever that audit says so. This inventory claims presence and traceability, not correctness.

**Coverage check (local HTML parser).** Expected 25 matching chapter stems; 50 chapter files; per language counts match. It found 36 chapter-local `sim-*` containers across 12 chapters, 65 rendered SVG/figure/canvas tags across the EN set (excluding external KaTeX, which renders math), and 230 external HTTP(S) anchor occurrences (links may repeat across chapters), and 25 paired source files in each language. The scan code is reproducible with the Python snippet below; counts are structural and do not assert that each control works.

```python
from pathlib import Path
import re
names = [p.stem for p in Path("chapters").glob("*.html") if p.stem != "resist"]
assert len(names) == 25
assert set(names) == {p.stem for p in Path("ko/chapters").glob("*.html")}
sim = figures = links = 0
for name in names:
    s = Path("chapters", name + ".html").read_text()
    sim += len(re.findall(r"<(?:section|div)\b[^>]*\bid=[\"\']sim-[^\"\']+", s))
    figures += len(re.findall(r"<(?:svg|figure|canvas)\b", s, re.I))
    links += len(re.findall(r"href=[\"\']https?://", s, re.I))
assert (sim, figures, links) == (36, 65, 230)
print(len(names), sim, figures, links)  # 25 36 65 230
```

## Source and diagram interpretation

- “Source anchors” are the chapter HTML’s external hyperlink labels and targets, enumerated from the EN file; the paired KO chapter is present but its exact link text/target can differ. This records attribution/link presence, not whether a source supports each nearby statement. Baseline/upstream links are included when explicitly cited in chapter HTML.
- Every simulator is client-side instructional code in page HTML and/or the listed local JS files. The common interaction framework is `js/common.js`; `js/xsec.js` implements the process-grid/diffusion model and cross-section rendering; `js/optics.js` supports lithography optics; `js/ldmos-sequence.js` renders named LDMOS sequence branches. Shared libraries do not mean each chapter has a physical simulator.
- Cross-section / technical figure elements are inventoried by the rendered `<svg>`, `<figure>`, and `<canvas>` IDs in each EN chapter row. CSS-only illustrations and inline image tags are not counted by the tag-count statistic; they remain part of source scope. The table's **`sim-*` containers** field counts only IDs with that prefix; “None” does not mean the page has no controls. Chapters 02–04 include inline calculators, Chapter 24 has the staged sequence viewer and editable XS lab, and Chapter 25 has glossary/quiz interaction. These interactions are described in their rows. HTML IDs beginning `sim-` identify interactive lab/calculator containers, not scientific model validation.
- Quantitative claim categories are concise chapter-level discovery summaries, not an exhaustive transcription of every numeral. Trivial UI values, quiz options/counts, navigation numbers, citation years, and numbers in names/identifiers are excluded from scientific-claim inventory. Include any number used as a physical input/output, measured/derived result, limit, range, tolerance, performance, reliability, geometry, or process condition in the relevant category above; source code/HTML remains the authoritative line-level locator.
- Critical nLDMOS chronology claims and exact source locators are separately itemized by IDs `NLDMOS-SEQ-001`–`004`, `NLDMOS-PBODY-001`, `NLDMOS-BODYTIE-001`, `NLDMOS-SOA-001`, and `MOS-PHYSICS-001` in the [critical claim register](V1_2_CRITICAL_CLAIMS.json), with opened-text locators/access notes in [source evidence](V1_2_SOURCE_EVIDENCE.md). Do not generalize the patent embodiments or infer foundry prevalence.
- This is a v1.2 working-tree inventory. It does not claim a complete independent scientific source audit, equation re-derivation, runtime QA, native-speaker translation review, foundry/process review, or production sign-off.
